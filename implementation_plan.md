### 1.2 Product Deep Dive — Steam Pet Grooming Brush

> [!IMPORTANT]
> What is marketed as "steam" is actually **cool-mist atomization technology** — dampening fur to reduce static and clump loose hair. This is safe and effective. Being transparent about this is a **key differentiator** against competitors.

**3-in-1 Value Proposition:**
1. **De-shedding** — removes loose undercoat fur
2. **Detangling** — mist softens knots for gentle brush-through
3. **Massage** — silicone/bristle nubs stimulate skin circulation

**Why It Wins on Social Media:**
- Visually satisfying "fur clump" result
- Before/after transformation format
- Works across all breeds (cats, dogs, rabbits)
- Emotional connection — pets visibly relax

## 🏗️ Part 3: Technical Architecture

### 3.1 Stack Decision

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| Monorepo Tool | **NX** | Best-in-class generators, caching, affected commands |
| Package Manager | **npm** (workspaces) | Native, no extra tooling, monorepo support via npm workspaces |
| Storefront | **Next.js 15** (App Router) | RSC, SEO, ISR for product pages |
| Admin Panel | **Next.js 15** (App Router) | Consistent DX, shared component library |
| Backend / API | **Supabase** (Edge Functions + RLS) | Zero server, auth, db, storage, realtime — all-in-one |
| Database | **Supabase PostgreSQL** | Managed Postgres with Row Level Security |
| Auth | **Supabase Auth** | Email/password + OAuth (Google, Apple) out-of-box |
| Server Logic | **Next.js Route Handlers** | Stripe webhooks, server actions, ISR revalidation |
| ORM / Query | **Supabase JS Client + Drizzle** | Type-safe queries, migrations |
| State Management | **Zustand** | Lightweight, no boilerplate |
| Styling | **Vanilla CSS + CSS Modules** | Full control, no runtime cost |
| Animations | **Framer Motion** | Professional animations |
| Forms | **React Hook Form + Zod** | Type-safe validation |
| Payments | **Stripe** | Industry standard, fraud protection |
| Email | **Resend + React Email** | Modern transactional emails |
| Image Storage | **Supabase Storage** + Cloudflare | CDN delivery, no extra service |
| Deployment | **Vercel** (both apps) | Serverless, free tier, global edge |

## 🔒 Part 6: Security Architecture

### 6.1 Authentication & Authorization

```
Storefront Customers:
  └── Supabase Auth (email/password + OAuth: Google, Apple)
  └── Session via @supabase/ssr in httpOnly cookies
  └── middleware.ts refreshes session on every request
  └── Row Level Security (RLS) — DB enforces data access

Admin Panel:
  └── Supabase Auth + custom claim: role = 'admin' | 'staff'
  └── middleware.ts checks role claim → redirect if unauthorized
  └── MFA enforced for all admin accounts (Supabase Auth settings)
  └── RBAC via Supabase custom claims (JWT metadata)

Edge Functions:
  └── Supabase service_role key (server-side only, never exposed)
  └── Functions are deployed on Supabase's Deno runtime
  └── Rate-limited at the Supabase project level
```

### 6.2 Payment Security
- ✅ **Stripe Payment Intents** — card data never touches our servers
- ✅ **Webhook signature verification** — `stripe.webhooks.constructEvent`
- ✅ **Idempotency keys** — prevent double-charging
- ✅ **Stripe Radar** — built-in ML fraud detection
- ✅ **3D Secure** — enabled by default for high-risk transactions

### 6.3 Infrastructure Security
- ✅ **HTTPS everywhere** — Cloudflare SSL
- ✅ **WAF** — Cloudflare Web Application Firewall
- ✅ **DDoS Protection** — Cloudflare
- ✅ **Environment Variables** — Never committed to Git (`.env.local` / Vercel env vars)
- ✅ **Secret Management** — Vercel env vars for `SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`

## ⚡ Part 7: Performance Optimization

### Frontend
- **ISR (Incremental Static Regeneration)** — Product pages cached, revalidated every 60s
- **Image optimization** — Next.js `<Image>` + WebP + AVIF
- **Font optimization** — `next/font` for zero layout shift
- **Code splitting** — Automatic by Next.js App Router
- **Bundle analysis** — `@next/bundle-analyzer`
- **Prefetching** — `<Link prefetch>` for key navigation paths
- **CSS-in-CSS** — No runtime CSS-in-JS overhead

### Backend (Supabase)
- **Supabase connection pooling** — PgBouncer built-in (Transaction mode for Edge Functions)
- **RLS policies** — Fine-grained row-level access, zero overfetching
- **Supabase Realtime** — Push order status updates to admin dashboard live
- **Pagination** — Cursor-based via Supabase `.range()` for orders/products
- **Database indexes** — On `slug`, `order_number`, `customer_id`, `status`
- **Edge Functions** — Run close to user on Deno Deploy globally

### CDN & Infrastructure
- **Vercel Edge Network** — Static assets globally distributed
- **Cloudflare** — DNS + WAF + CDN for images
- **Core Web Vitals targets:** LCP < 2.5s, CLS < 0.1, FID < 100ms
